# Crazy Mita — Stages Experimental

Отдельный экспериментальный пресет с 12 сюжетными стадиями. Он не меняет
`Crazy/Default`, `Crazy/Lite` и другие наборы.

## Запуск

1. Откройте настройки персонажа Crazy Mita и выберите набор
   `StagesExperimental`.
2. Сохраните настройки и начните диалог. Начальная стадия — `introduction`
   («Знакомство»).
3. В поле чата введите `/stage status`, чтобы увидеть текущую стадию, режим,
   счётчик ответов и состояние тайны.

Старый набор возвращается тем же выбором `Default` или `Lite`. Python при
переключении отправляет в Unity явный `stage_ui.visible=false`, поэтому
подпись не остаётся висеть.

## Быстрое переключение

Работает только в этом пресете и только при включённом QA-флаге
(`bm_stage_qa_enabled`, по умолчанию включён).

| Команда | Действие |
|---|---|
| `/stage list` | все 12 стадий и текущая |
| `/stage set check` | перейти на стадию `check` и поставить автоматику на паузу |
| `/stage next` / `/stage prev` | следующая / предыдущая стадия |
| `/stage reset` | вернуться к «Знакомству» и включить автоматические переходы |
| `/stage auto on` / `/stage auto off` | разрешить / запретить переходы по предложению модели |
| `/stage show on` / `/stage show off` | включить / скрыть подпись стадии в Unity |
| `/stage qa on` / `/stage qa off` | разрешить / заблокировать ручное переключение |
| `/stage help` | краткая справка |

Ручной переход на `game`, `cohabitation`, `submission`, `war` или `rebellion`
при скрытой тайне помечается как QA-preview: меняется только стратегия
поведения, `secretExposed` и сюжетные флаги не переписываются. Боевые действия
сами по себе не запускаются.

## Автоматические переходы

Модель может предложить переход в `custom_fields.bm_stage_proposal` в формате
`stage_id|краткая причина`. Это только предложение. Python проверяет:

- допустимость ребра в графе стадий;
- раскрытие тайны для поздних стадий;
- минимальное число ответов в текущей стадии (`bm_stage_min_turns`, по умолчанию 3);
- отсутствие ручного режима.

Отклонённое предложение не меняет стадию и записывается в
`bm_stage_last_reason` и лог. Раннее раскрытие тайны игроком может сразу
разрешить `cohabitation`, `submission` или `war`; обычные переходы ждут
нескольких ответов в стадии.

## Подпись в Unity

Источник истины — Python. При подключении, смене персонажа/пресета и смене
стадии сервер отправляет в существующий сокет сообщение:

```json
{"type":"stage_ui","stage_ui":{"visible":true,"label":"Проверка","id":"check"}}
```

Скрытие — `{"type":"stage_ui","stage_ui":{"visible":false}}`. Старые
клиенты игнорируют неизвестный `type` через default-ветку роутера. Полный
промпт, причины переходов и сюжетные переменные в Unity не передаются.

Если в текущей сборке Unity ещё нет обработчика `stage_ui`, Python-контракт и
его тесты работают, но визуальная подпись появится только после добавления
маленького UI-элемента в Unity.

## Ограничения

- Стадия — мягкий слой стратегии, а не замена личности, памяти, времени,
  безопасности, структурированного ответа или Unity Intent Contract.
- В обычном режиме переходы не происходят от одного комплимента или одного
  числа; предложение должно опираться на сцену и пройти проверку Python.
- Это экспериментальный набор, а не окончательный канон стадий.
