# Unity World State: стабильные контракты, состояние хода и одноразовые события

**Назначение:** описать, какие сведения о подключённом Unity-мире попадают в Core, как превращаются в контекст конкретной LLM-генерации и какие данные должны переживать один запрос. Исследуются пользовательские механики — восприятие состояния окружения, доступных действий и событий, а не устройство старого Python-класса как целевой модели Rust.

**Статус:** **ACTIVE/CONDITIONAL** при подключённой Unity и соответствующих событиях. **Источники:** `src/game_connections/handlers/actions/create_task.py:344-393`; `src/managers/game_state_manager.py:8-61`; `src/controllers/model_controller.py:306-329,1409-1429`; `src/controllers/prompt_controller.py:654-834,854-908,1026-1079,1118-1183,1243-1257`.

## CAP-WORLD-STATE-001 — модель состояния окружения на входе Core

`create_task` собирает из event context несколько различных классов данных:

| Срез | Примеры полей | Семантика |
|---|---|---|
| Присутствие и окружение | `distance`, `roomPlayer`, `roomMita`, `nearObjects` (`hierarchy` у источника) | Текущее положение и видимый контекст |
| Мировой snapshot | `world_state`, `worldPlayer`, `worldMita` | Факты о конкретном мире; world IDs имеют fallback из `world_id` и `dialogue.world_id` |
| Правила выполнения | `runtime_rules`, `intent_rules`, `runtime_static_catalog` | Определения поддерживаемых каналов, интентов и стабильных исполняемых идентификаторов |
| Моментная доступность | `runtime_capabilities` | Доступные **сейчас** каналы/действия, которые могут зависеть от состояния игры |
| События текущего хода | `runtime_events`, `tv_observation` | Наблюдения с ограниченной жизнью: не переносить их в следующий запрос как «последнюю правду» |

`GameState` хранит по character последние известные базовые значения и допускает частичное обновление по новым сообщениям. `ModelController._on_set_game_data` использует `character_id`, при его отсутствии — текущего персонажа, обновляет per-character game state и отдельную общую выжимку shared world facts. При чтении `_get_game_state_for_character` возвращает dict, включая копию `shared_world_info`. Отсутствие собственного состояния порождает значения по умолчанию — это не подтверждённая игровая сцена.

`create_task` передаёт текущее событие отдельно в generation request и отправляет в `SET_GAME_DATA` его **persistent fallback subset**: из него исключены `runtime_events` и `tv_observation`. Другие поля могут сохранять last-known values между ходами. Это функциональное различие между последним состоянием, свежим событием и одноразовым наблюдением.

## CAP-WORLD-STATE-002 — формирование двух частей prompt-контракта

**Стабильная часть** при наличии содержимого:

- `[Unity Runtime Rules]`: описание поддерживаемых исполнительных каналов.
- `[Unity Intent Contract]`: типы и payload игрового intent, **только если** DSL/policy разрешают `support_intents`; реакция L1 отключает этот режим.
- `[Unity Static Catalog]`: стабильные идентификаторы, не обещающие доступность действия прямо сейчас.

Эти system-блоки формируются *до* истории/summary, в стабильном префиксе запроса. Это позволяет сохранить предсказуемый контекст и совместимо с provider prompt caching; не следует смешивать их с мгновенной готовностью каждого действия.

**Динамическая часть** идёт ближе к текущему запросу:

- `[Unity Runtime Capabilities]`: исполняемые идентификаторы, доступные именно на текущем ходе; текст маркируется как event/data, а не новое правило.
- `[NeuroMita World State]`: окружающие факты и восприятие персонажа в роли event/data.
- `[Shared Unity World Info]`: пассивные общие факты о мире игрока, включая world и room id.
- `[Character World Context]`: персональное значение места для конкретного персонажа (описано [отдельно](../01-functional/character-world-and-environment-awareness.md)).
- `[Unity Runtime Events]`: события, накопившиеся после предыдущего turn; директивы GameMaster извлекаются из них отдельно и ставятся позднее как специальные сообщения.

`PromptController.build()` подавляет **и статический, и динамический** Unity-контекст при достоверном `request_runtime.connected is False`. При неизвестном статусе (`None`) он не делает вывода, что игра отключена. Это предотвращает выдачу устаревших игровых фактов за настоящее при обычном desktop диалоге без Unity, сохраняя отдельную semantics last-known state.

### Отношение к другим контекстам

- `Current State` включает локальные дату/время и — при разрешённой настройке — время с последнего сообщения. Для Player turn с паузой от 30 минут подмешивается мягкая инструкция реагировать на возвращение, зависящая от длительности; это поведенческая подсказка, не Unity event. Источник: `prompt_controller.py:587-645,1185-1202`.
- Общие мини-игровые сведения могут передаваться *не участнику* активной мини-игры как read-only `[Shared Mini-game Context]`. Текст прямо запрещает выпускать игровые команды на основании чужой сессии. Источник: `prompt_controller.py:730-759,1144-1149`.
- Current character stats и пользовательские поля формируют отдельный `[Behavior State]`; он может заменяться custom profile, что описано в [персонажах](../01-functional/characters.md).

## CAP-WORLD-STATE-003 — сохранение смысловой границы данных и инструкций

В данных мира могут содержаться тексты, на которые влияет игрок. `PromptController._neutralize_world_state_tags()` заменяет `[`/`]` у зарезервированных управляющих маркеров и любых закрывающих тегов на визуально похожие символы. Это не пользовательская настройка и не гарантия защиты от всех возможных prompt-injection, а конкретный контракт **представления недоверенных игровых фактов как данных**. Инструкции о допустимых действиях приходят из выделенных проверенных rules/intent contract, не из произвольной строки world state.

## Сценарии для проверки полного паритета

1. Один персонаж получает два последовательных частичных обновления game state: сохраняются известные поля, мгновенные events не переносятся автоматически в будущие turns.
2. Одновременный ответ разных персонажей: каждый видит свой snapshot/lore, shared facts читаются без подмены identity.
3. Соединение Unity теряется: desktop turn не содержит устаревшее `[NeuroMita World State]` даже при last-known cache.
4. Статический канал/идентификатор указан в catalog, но временно недоступен в `runtime_capabilities`: модель должна различать возможность *в принципе* и доступность *сейчас*.
5. `support_intents=false` или реакция L1 — в prompt нет активного Unity Intent Contract; текст мира не становится основанием отправлять запрещённые intents.
6. События текущего хода, GM directive, общая мини-игра и последнее отсутствие игрока отображаются в соответствующих **разных** контекстах.

**Функциональные требования для будущего Core:** различать стабильный capability catalog, динамический snapshot, моментные события, индивидуальный характерный контекст и источники инструкций. Ни один из этих контрактов не требует наследования `GameState` или `PromptController` в Rust; форма реализации выбирается после полного аудита.
