# Первый запуск: EULA, выбор языка и переход к руководству

**Назначение:** описать наблюдаемый сценарий допуска пользователя в обычную GUI NeuroMita. **Статус:** `CONDITIONAL` для первого запуска, сам механизм `ACTIVE`. **Источник:** локальный Python-срез `CodeNow.zip`, commit SHA не подтверждён; GUI на Windows не запускался. Это продуктовая функциональность, не перенос текущей QWidget-структуры.

## CAP-UI-ONBOARD-001 — first-run acceptance gate

`src/ui/windows/app_window_base.py:246,1660-1695`; `src/ui/widgets/eula_widget.py:10-25,184-202,236-248`; `src/ui/widgets/overlay_widget.py:31-45,77-82`.

Через 1000 ms после построения главного окна вызывается `_check_eula_and_guide`: при `EULA_ACCEPTED == False` поверх приложения открывается обязательный `EULAWidget`. Вызов `overlay.set_content(widget, locked=True)` блокирует штатное закрытие по клику на фон; это модальный **presentation gate**, но из этого не следует остановка всех фоновых Core-сервисов или сетевых процессов.

| Действие | Эффект | Следующий шаг |
|---|---|---|
| Прочитать соглашение | Read-only scrollable text, переводы по языку | Доступны Accept/Reject |
| Выбрать язык | Меняет язык текста соглашения, названия кнопок и заголовок сразу | Не считается согласием, не меняет текст содержимого Core |
| Принять | `LANGUAGE` устанавливается в выбранный код; `EULA_ACCEPTED=True`; сигнал `accepted` | Оверлей скрывается; возможно предложение рестарта языка; затем Guide |
| Отказать | Сигнал `rejected`, критический информационный диалог, `main_window.close()` | Приложение закрывается |
| Обычный повторный GUI-запуск | При сохранённом `EULA_ACCEPTED=True` обязательный оверлей не показывается | Запускается пользовательская оболочка; автоматический Guide в этой ветке не вызывается |

**Границы проверки:** `EULA_ACCEPTED` используется как persisted setting, но в исследуемом фрагменте не найдена version-aware повторная акцептация новой редакции соглашения. Нет подтверждённого EULA gate в headless startup: это именно GUI-ветвь. Не следует добавлять такую headless блокировку в обязательную совместимость без продуктового решения.

## CAP-UI-ONBOARD-002 — язык до согласия и локализованные тексты

`src/ui/widgets/eula_widget.py:166-181,210-245`; `src/localization/eula_texts.py:419-435`; `src/localization/__init__.py:184-254`.

Языки перечисляются из catalog discovery (встроенные JSON + внешние пользовательские локали). Но **полный EULA-текст** берётся из отдельного `EULA_TEXTS`: на выбранный неизвестный язык используется английский текст соглашения, даже если обычный UI имеет JSON-каталог этого языка. Название языка в переключателе получается через `language_display_name` и может учитывать `_name` custom JSON.

При Accept код записывается в `LANGUAGE`. Если выбранный язык отличается от того, на котором уже построена главная оболочка, вызывается `prompt_language_restart`. Это отличается от штатного **live UI language switching**, поскольку первая EULA отображается поверх уже созданного окна. Отказ от перезапуска не отменяет принятие и последующий guide. Это пользовательский сценарий, который нельзя упустить при полной переписи интерфейса.

## CAP-UI-ONBOARD-003 — открытие Guide после согласия

`src/ui/windows/app_window_base.py:1673-1710`; `src/controllers/gui/dialog_controller.py:45-52`; `src/controllers/gui/window_composition_controller.py`; `src/ui/windows/guide_dialog.py`.

После принятия EULA и закрытия оверлея `QTimer.singleShot(500, self._show_guide)` открывает зарегистрированный dialog `guide` через WindowManager. Guide получает действие `open_wiki`, которое делегируется `page_actions.open_wiki_document(target)` — это полноценная навигация из обучающего материала к документации, а не просто статичная заставка. Если выбранный после EULA путь перезапуска выполнен, текущий callback прекращается до планирования Guide. Сам Guide/интерактивные скриншоты подробно описаны в [отдельном аудит-документе](guide-walkthrough-and-image-focus.md).

## Пользовательские состояния и требования

**Состояния:** first launch detected → agreement visible → `(language changed?)` → accepted/rejected → optional restart → guide or close. Сохранённый consent (`EULA_ACCEPTED`) не равен установленной локали (`LANGUAGE`), а открытие Guide не равно согласию. Эти независимые факты важны для возможной Rust UI реализации.

- `REQ-UI-ONBOARD-001`: иметь определённый first-run consent flow с сохранённым выбором, допускающим закрытие приложения при отказе; условие показа, версия согласия и scope GUI/headless должны быть сознательно специфицированы.
- `REQ-UI-ONBOARD-002`: показывать доступные языки и полный многострочный текст соглашения с явным fallback, не путать стандартный UI-каталог с отдельным EULA translation corpus.
- `REQ-UI-ONBOARD-003`: после согласия предложить переход в Guide и Wiki, сохранить документируемую семантику выбора языка в момент уже построенного GUI.

**Проверки паритета:** новый GUI без consent; сохранённый consent; выбор другого языка на EULA; custom locale без полного EULA текста; Accept+не перезапускать; Accept+перезапустить; Reject; Guide → Wiki; headless без GUI; failed settings persistence (что делать — требуется продуктовая политика).

**Оставшиеся вопросы:** юридически актуальная редакция EULA, необходимое version re-acceptance, first-run-guide независимо от consent, accessibility/keyboard-only acceptance и требования к неинтерактивным режимам. Это вопросы продуктового контракта; старый код не определяет за новую систему ответы.
