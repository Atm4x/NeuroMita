# Актуальная база функционального аудита

Срез: **2026-10-31, Pass 13**. Начинать чтение с этого документа. Остальные checkpoint/handoff записи сохраняют историю исследования; их «следующий шаг», временной лимит, количество файлов и результаты тестов не заменяют этот срез.

## Объект и результат

Исследуется **поведение Python-приложения и его core dependencies** для переписывания с нуля. Сохраняемые возможности формулируются через вход, состояние, результат и ошибки. Python classes/managers, EventBus, SQLite layout и queues — свидетельства действующей реализации; их копирование не является требованием новой архитектуры.

**Не входит в текущую фазу:** сравнение Qt/Slint/других GUI; итоговая Rust-архитектура; подробная реализация Unity-клиента; переписывание inference на Rust. Функциональные действия нынешнего GUI входят: именно оттуда запускаются многие команды.

Полный аудит **ещё не объявлен закрытым**. Основные контракты всех 20 областей представлены материалами, но у семи исторически PARTIAL областей остаются source-depth или runtime validation gates. Число документов, найденных callbacks или passed tests не является процентом завершения всего аудита. Фиксированная шкала PRIMARY/PARTIAL сохранена в [ledger](audit-coverage-ledger.md), без пересмотра её критериев ради роста процента.

## Что добавил и действительно исполнил Pass 13

1. **RAG SQL fixture:** выбранные неизменённые repository methods, temporary SQLite/FTS5; другой embedding model, legacy BLOB, отсутствие vector, character isolation, memory eternal_id. PASS. Не ranking/inference E2E.
2. **Node editor parser/codegen fixture:** SET/RUN/RETURN выявляет unsupported RUN и его отсутствие после graph regeneration. PASS assertions; это подтверждённое ограничение, не успешный lossless editor.
3. **World DB fixture:** scope/status/date, исключение embeddings, remap/new IDs, repeat import при заданной схеме, variables replace, transaction rollback. PASS после исправления уборки собственных fixture connections. Не пользовательская БД и не migrations E2E.
4. **History presentation fixture:** stale/superseded request, wrong/inactive character, casefold и live replay. PASS. Не Qt scroll/SQLite/network E2E.
5. **Legacy inspection/replay fixture:** folder/files/ZIP/moved path digest, counts/warnings, partial memories, mixed-character/unsafe member rejection и ordered update/delete. PASS. Не DB import/backup/WAL и не реальные пользовательские exports; [условия](../01-functional/compatibility-imports.md).
6. **Read-only dependency evidence:** 131 local METADATA; native entries выбранных RECORD; import tables шести существующих PE binaries. DLL не исполнялись, пакеты не устанавливались. Upstream/registry данные Rust alternatives проверены по первичным источникам, ссылки/даты находятся в dependency reports; Rust builds/corpus benchmarks не выполнялись. Дополнительный AST scan 717 src + 14 scripts + 39 editor modules уточнил [extension/language boundary](../04-dependencies/dynamic-import-registries-and-runtime-capability-contracts.md).

## Порядок следующего продолжения

1. S-SET/S-UI: использовать имеющиеся 99-key/517-connect/52-async индексы как очередь, сверять **ещё не описанный outcome**, а не заново считать литералы. Для каждого дополнительного source path добавлять ссылку в traceability; не объявлять все indexed calls проверенными по имени handler.
2. S-DATA: реальные compatibility samples и допустимые изолированные storage fixtures для snapshot/live state, import→reindex/graph и concurrent mutation. Не открывать пользовательские saves или выполнять destructive операции на них как тестовую базу.
3. S-REACH: оставшиеся непрямые event/settings registrations; для unproven/standalone держать отдельный статус, без превращения класса в обязательную capability.
4. V-ENV: отдельно от source audit формализовать целевую Windows/AI/device/network validation среду и её exact revision/lock. Уже описанные 0/31 physical install checks не скрывать и не заменять unit counts. Архитектурный проект и GUI comparison всё ещё отложены.
5. T-TRACE: свести остаток с реестрами entrypoints и requirements; общий процент не вычислять из количества заметок/тестов. При пользовательском quota cutoff сохранить точку и остановиться без заявления о завершённом полном аудите.
