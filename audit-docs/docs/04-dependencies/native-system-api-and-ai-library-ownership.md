# Нативные системные API, драйверы и библиотеки Python AI: подтверждённое функциональное владение

**Назначение:** отделить то, ради чего NeuroMita обращается к Windows/драйверу/внешнему исполняемому файлу, от Python-wrapper, через который это сделано сейчас. Это часть dependency audit **перед** проектированием нового Rust Core с нуля. **Источник:** локальный `CodeNow.zip`; без проверки DLL на действующей Windows-машине, без установки новых компонентов и выбора crates.

## Различные классы `native dependency`

1. **Windows SDK/system DLL:** `dxgi.dll`, `ole32`, `user32`, `kernel32` — часть платформы. Функциональные требования: hardware inventory, audio identity, process/window management, path compatibility. Они не являются `pip` зависимостями пользователя.
2. **Драйвер и device availability:** `nvcuda.dll` обнаруживается лишь при наличии подходящего NVIDIA driver; наличие API в коде не означает доступную CUDA. Windows DXGI может работать независимо и выдавать AMD/Intel/NVIDIA GPU. На production path `_attach_cuda_devices_to_adapters` сопоставляет LUID и fallback по **уникальному** нормализованному имени (`hardware_inventory_service.py:234-350`).
3. **Обязательные для определённой optional capability binary tools:** FFmpeg для конвертации media, PortAudio endpoint/driver для microphone capture, Unity.exe для actual game session, модельные weights и Python runtime packages для TTS/ASR/RAG/Beat. Их наличие, установка и ready status — разные состояния.
4. **Python wrappers с replaceable функциональной ролью:** `pywin32` (window capture/Auth DPAPI), `sounddevice`, `pygame`, `psutil`, `pywinpty` имеют приложения к core или tooling. В новом Rust Core сохраняется **пользовательская операция**, не тождественная зависимость от их Python SDK.
5. **Сторонние AI native runtimes/модели:** PyTorch, ONNX Runtime, transformers, CUDA kernels, VAD и их нативные зависимости остаются за границей Python AI Engine, если нет отдельного нового продуктового решения об inference. Core управляет installation/probe/IPC/supervision, но не обязан линковать эти runtime.

## CAP-DEPS-NATIVE-001—004: требования и проверяемый паритет

- `REQ-NATIVE-001`: Windows GPU inventory должно строиться без необходимости запускать Python AI worker, различать фактическую физическую карту и CUDA device assignment и поддерживать refresh/cache status. Проверять no NVIDIA / 1 GPU / multiple identical-name GPUs / disabled driver.
- `REQ-NATIVE-002`: Audio input device identity должна поддерживать hotplug, повторное перечисление и однозначное сопоставление endpoint; использовать устройство в audio capture только при фактическом device readiness, независимо от готовности ASR-модели.
- `REQ-NATIVE-003`: При обновлении Unity coordinator должен проверять **конкретный путь executable**, инициировать graceful shutdown, обрабатывать отказ/тайм-аут и не считать закрытие окна эквивалентным завершению процесса.
- `REQ-NATIVE-004`: Ключи пользователей и системные разрешения на Windows являются собственными Core контрактами; AI-model DLL/cuda kernels и CUDA interpreter stack не становятся транзитивной обязательной частью Rust executable.

**Открытые проверки:** Windows deployment native loader graph; точные зависимости FFmpeg binary и CUDA/DirectML по каждой model selection; DLL search path/VC runtime для TTS; ABI/лицензии; фактическая совместимость с Windows без драйвера; собственные credential stores других provider; набор optional installer packages по wheel metadata. Это **не** выдуманная readiness-матрица и не инструкция выбирать Rust crates заранее.
