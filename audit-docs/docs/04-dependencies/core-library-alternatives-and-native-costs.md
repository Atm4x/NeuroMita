# Core libraries: проверенные варианты, ограничения и native cost

Дата проверки: 2026-10-31. Это dependency audit: конкретные API/границы/лицензии, не утверждённый Rust stack и не проектирование модулей. GUI comparison исключён. [Нишевые зависимости](core-niche-alternatives-and-parity-gates.md) разобраны отдельно; [Python/transitive evidence](installed-wheel-metadata-and-native-evidence.md) отделён от будущих native dependencies.

Ни одна строка не означает, что crate уже реализует очередь NeuroMita, диалоговые эффекты, контракты истории, presets или безопасное обновление. Эти части сейчас преимущественно собственный Python-код; под Rust их проектируют заново после аудита.

## Ответ на вопрос об обязательном Python Core

По подтверждённым active/conditional **не-AI** функциям requirements не выявлен hard blocker «эта возможность исполнима только из Python и принципиально недоступна Rust host». Для сложных случаев существуют native Rust или C/C++/OS API пути. Сильнее всего требуют parity/provenance проверки русская морфология, многоязычные числительные, Telegram user sessions, malformed JSON/effect trust и media/platform integration.

Это не утверждение полного replacement всех84 строк один-к-одному. Часть строк — transitives/SDK без подтверждённого active ingress, часть — Python AI tooling. Отсутствующие imports не основание удалить пользовательскую функцию, а наличие Python wrapper не основание удерживать Python Core. Полный functional catalog и признанные validation gaps остаются источником требований; GUI/architecture выбор данным отчётом не сделан.

## Pass 13: NumPy не целиком принадлежит inference

Read-only source search показал NumPy в Core RAG repositories/query/scoring, MemoryDeduplicator, graph similarity, embedding provider result decoding, MicrophoneMonitor и optional WAV amplification. При классификации requirements нельзя целиком пометить numpy как AI-only и потерять эти функции. Веса/forward/ASR/TTS model execution остаются Python; norm/dot/top-k, buffer interpolation и clipping не требуют Python по природе задачи.

`services/microphone_monitor.py::MonitorBuffer` держит mono float32 FIFO не более примерно 120 ms входных samples, интерполирует позиции с отношением input_rate/output_rate, сохраняет fractional position между read, отдаёт недостающие frames нулями и при overflow оставляет newest tail. Это функция прослушивания микрофона с разными device rates, а не audio inference. `AudioHandler._amplify_wav` читает float32, умножает gain, clip[-1,1] и пишет временный WAV; при недоступности NumPy/soundfile возвращает None и playback откатывается к ограниченному mixer volume.

`pipeline/retrievers/faiss_index.py` имеет exact matrix path и exact FAISS IndexFlatIP path, несмотря на слово ANN в верхнем комментарии. Обе ветки возвращают source ID + score; model/character scope и invalidation описаны в [RAG provenance](../01-functional/rag-mixed-model-recall-and-provenance.md). Alternative ANN engine допускается только новым решением о recall/latency, не как доказанный функционально равный перенос. Ни comparative numeric/Rust benchmarks, ни sound hardware/FAISS native builds здесь не запускались.

## Pass 13: packaging и locking — реальные Core consumers

`core/install_requirements.py::is_pip_spec_satisfied`, InstallController, backend service, runtime environments и pip_installer используют packaging не ради inference, а для нормализации имён, Requirement, marker и version checks. Пример текущего контракта: false marker → satisfied; installed version проверяется `specifier.contains(..., prereleases=True)`; registered checker может дополнительно проверять import/files; нет metadata или ошибка парсинга не равны успешной загрузке модели. При отсутствии packaging отдельные fallback ветки слабее: они могут проверить только package/module presence.

В дочитанных вызовах `req.marker.evaluate()` explicit target environment не передаётся. При separate managed Python/host identities новая система должна определять, для какой Python version/platform/extras вычислен marker, а не просто заменить PEP parser на SemVer. Acceptance: canonical-name aliases, extras, `python_version`/platform markers, pre/dev/post/epoch/local versions (`+cu...`), target metadata vs реально importable package, marker-excluded dependency. Rust parser corpus здесь не запускался.

`chatgpt_plan_auth.py::_session` берёт threading.RLock, пропускает повторный file lock при nested depth, затем portalocker `.lock` с 300s timeout, перечитывает latest state и выполняет операцию. Это межпроцессная синхронизация auth store; DPAPI protection и atomic save — отдельные свойства. Не открывались реальные account files и не выполнялись login/refresh. Future fixture: два процесса, nested call, stale disk state, timeout/cancel, crash/reopen. File locking не является Python-only capability.

## Pass 13: implicit process-control dependency

psutil не объявлен корневой строкой requirements, но найден в **четырёх** src modules: active `services/unity_process_guard.py`, active HomePageController, compile-cache tooling `core/torch_compile_runtime.py`, standalone HOI4. Его локальная metadata также присутствует как dependency py7zr (вне Cygwin). Следовательно отсутствие root requirement или первый найденный HOI4 import не делает psutil целиком экспериментальным/AI-only.

Python-facing функции: восстановить/обнаружить внешний Unity process по executable и PID/create_time, показать running/stopping/error, остановить выбранный процесс; перед update запросить закрытие, ждать 5s, при необходимости terminate/kill и ждать ещё 3s, повторно проверить newly running processes до replace. Отдельная directory-user диагностика смотрит exe/cwd и прямо не обещает полный список file handles/DLL locks.

Compile cache removal при PermissionError сканирует memory_maps; автоматически завершает только совпавший managed Python multiprocessing.spawn/spawn_main с отсутствующим parent, после чего повторяет удаление и даёт diagnostic error при оставшемся lock. Это source behaviour и gate проверки process ownership, не действие, выполненное аудитом. Никакие процессы пользователя не перечислялись через psutil, не останавливались и cache directories не удалялись.

Rust/system paths для этих возможностей существуют. На новом проекте надо определить ownership/identity/timeouts и диагностическое покрытие, а не воспроизводить всю psutil API. Windows process permissions, PID reuse/respawn, stale marker и locked cache относятся к future native fixtures.
