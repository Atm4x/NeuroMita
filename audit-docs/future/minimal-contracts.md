# Минимальная реализация обсуждённых контрактов

Актуальный статус после [первого среза](first-slice.md). Проект: [rust](../rust/README.md). Чеклист: [implementation-checklist](implementation-checklist.md). Детали передачи: [HANDOFF](../rust/HANDOFF.md).

## Что реализовано

| Контракт | Реализация |
|---|---|
| Статические входы | ChatApi::reply/react/initiate/send, CharacterApi, SettingsApi |
| Типизированные сообщения | ReplyRequest, ReactRequest, InitiateRequest; Message; обязательный пресет, input/source, явные intent/at/voice |
| Приём и очередь | Ограниченный mpsc на персонажа, короткий admission lock, немедленный RequestHandle или явный отказ |
| Конкурентность | Разные персонажи генерируются параллельно; один персонаж принимает предыдущий результат перед следующей работой |
| Владение | CharacterRegistry выдаёт handles владельцев; CharacterHandler отдельно обслуживает свой mailbox |
| Субъективный контекст | CharacterHandle::get_context(at), prepare запроса, история только известных персонажу событий |
| Timeline | Vec, EventId, branch ID и through; at_event, read_at, наблюдения, reply/react/initiate и причинные ссылки |
| Генерация | Общий GenerationProvider, типизированные ProviderTemplate/GenerationPreset, отдельный GeminiTemplate и wire-модуль |
| Подготовленный результат | ProposedResponse с текстом и ResponseEffect; нет мутации Character при получении текста |
| Озвучка | VoiceProvider/VoicePlan/VoiceOptions/AudioArtifact, GeneratingVoice, успех или ошибка с рабочим текстом |
| Принятие | Working/Accepting/Applied/Discarded, атомарная гонка с отменой, Finished после применения |
| Наблюдение | Watch снимков одного запроса и согласованное discovery новых обращений из всех источников |
| Диагностика | Ограниченный RequestTrace отдельно от SessionTimeline: input, безопасное описание пресета, контекст, текст, переходы |
| Настройки | Структуры разделов, проверка, CAS по revision, атомарные edit, наблюдение и состояние сохранения |
| SettingsLifecycle | Memory/JSON repository, фоновое сохранение, flush, явный retry, защита от запоздалой ошибки старой попытки |
| Presenter | GuiPresenter с ChatPresenter, SettingsPresenter, CharactersPresenter |
| Binding | BoundProperty<T>: get/set/observe; подтверждённые значения, ошибки и изменения из внешних источников без обратной записи |
| Lifecycle | Общий trait; ApplicationLifecycle, SettingsLifecycle и ServerLifecycle |
| Сеть | TCP line protocol: connected/read, test → ChatApi, статусы, настройки, отмена, bounded outbound и shutdown |

## Жизнь запроса

Pending → Processing(GeneratingText) → Processing(GeneratingVoice), если озвучка запрошена → принятие → Finished. Публичный Processing не раскрывает внутренний Accepting.

Итоги: Success, TextGenerationFailed, VoiceGenerationFailed с принятым текстом, InternalError с доступным частичным текстом. Отмена до принятия даёт Cancelled и не применяет эффекты.

VoiceGenerationFailed означает: генерация текста успешна, он и связанные эффекты приняты; аудио отсутствует. Если пользователь отменил ожидающую озвучку, ответ и эффекты не принимаются. API отмены после входа в Accepting возвращает TooLate.

Провайдер текста возвращает сырой видимый текст. ResponseGenerator формирует ProposedResponse и план эффектов; исполнитель передаёт этот план владельцу. Сейчас содержательный эффект минимален: RecordAcceptedReply. Владелец валидирует весь пакет до изменения памяти, записывает ответ в timeline и обновляет state в одном коротком участке. Обработка дополнительных эффектов расширяется здесь, а не в UI.

## at и состояние персонажа

ContextPosition::Latest фиксируется при начале обработки. ContextPosition::At(anchor) читает выбранный префикс и состояние, восстановленное по этому префиксу для минимального счётчика ответов. Текущий вход учитывается отдельно.

Факт реакции разрешён только для известного данному персонажу события. Приватное наблюдение другого персонажа не открывается реакцией.

Запрос со старым состоянием не применяет эффект к изменившемуся Character: при принятии проверяется revision. В этом случае возвращается InternalError с подготовленным текстом. Снимок истории и состояние не смешиваются молча.

Это минимальный механизм адресации, не полная реализация forks, сброса знаний и checkpoint restoration.

## Настройки и представление

SettingsApi предоставляет typed snapshot/replace/edit и observe. AppSettings содержит VoiceSettings, CaptureSettings, InterfaceSettings. Volume проверяется как тип, комбинации полей валидируются перед публикацией. Обязательные поля файла не восполняются через Default.

SettingsSource::Initial и SettingsSource::Stored выбираются явно. initial_profile — явная конфигурация минимального запуска, не fallback после ошибки загрузки.

SettingsPresenter отдаёт bindable volume/in_launcher/in_game/voice. Setter выполняет атомарный edit через SettingsApi. Observer публикует значения из источника, но не вызывает setter. Модель обновляется также при сетевой команде изменения настройки.

Сохранение отделено от принятия значений. Ошибка IO видна в SettingsSnapshot и flush. retry_save начинает новое поколение попытки, поэтому старая ошибка не перезаписывает состояние нового retry. Закрытие завершает наблюдение свойств явным Stopped и сохраняет последнее принятое состояние.

Конкретные Slint widgets и TUI renderer намеренно не добавлены: реализован контракт, к которому подключается frontend.

## ServerLifecycle

Не привязан к Unity. Сервер владеет listener, клиентскими задачами, выходными очередями и наблюдением, вызывает статические Api. Команда test создаёт обычный запрос от клиента; GUI presenter замечает его через registry.

Сетевой протокол описан в [README](../rust/README.md). У каждого соединения отдельные client ID, очередь отправки и квитанции. Отмена чужого запроса не допускается. Разрыв соединения прекращает наблюдение, но не отменяет принятую работу ядра.

Повтор JSON-команды с тем же command_id в окне квитанций возвращает тот же RequestId. Изменение содержимого при том же ID даёт ошибку. Обычный повтор текста с новым ID — новое обращение. Дедупликация между переподключениями/рестартами не обещается.

## Что сознательно остаётся минимальным

- Факты timeline и технический журнал запросов в памяти; нет SQLite и восстановления после crash.
- Один timeline branch; нет тяжёлой системы веток/сохранений.
- Реальный TTS-движок не подключён. По умолчанию VoiceProvider возвращает Unavailable; контракт проверен управляемым тестовым исполнителем. Это не имитация работающей озвучки.
- Стартовые персонажи имеют минимальные новые descriptions/prompts, а не весь набор функционала Python-персонажей.
- Нет tools, мультимодального ввода и потока текстовых чанков; речь идёт о контрактах, обсуждённых для запроса.
- Discovery имеет ограниченный буфер, отставание объявляется ошибкой; бесконечного replay нет.
- Сетевой протокол тестовый, с ограничением размера/очередей; полноценная аутентификация и совместимость с текущим Unity протоколом не реализуются этим срезом.

## Проверка

contracts.rs проверяет настроечные snapshots/binding/CAS/save/retry, минимальный at, известность событий, reply/react/initiate, голосовой успех/ошибку/отмену, пакет эффектов, RequestTrace, TCP test, доставку статусов, повтор команды и фрагментированный ввод при обновлении настроек.

vertical_slice.rs проверяет реальный HTTP-адаптер формата Gemini с локальным сервером, конкурентность персонажей, очереди, ошибки, отмену и остановку. Unit-тесты проверяют race отмены/Accepting и старой ошибки сохранения, строгую конфигурацию и decode Gemini.

Живой тест Gemini прошёл 2026-11-01 с явно выбранным пользовательским пресетом Main / gemini-3.6-flash: ответ «Готово.» за 1,99 секунды. Proxy env были очищены в тестовом процессе, системный Windows-прокси подхвачен автоматически. В reqwest явно включены system-proxy и http2; отсутствие system-proxy в первоначальной конфигурации объясняет прежний TCP timeout. HTTP/2 подтверждён отдельной проверкой без ключа к тому же хосту. Ключ не выводился, не менялся и не сохранялся.
