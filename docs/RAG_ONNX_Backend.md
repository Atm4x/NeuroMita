# Локальный RAG через ONNX / DirectML

Экспериментальный бэкенд для эмбеддингов и реранкера. Настройка
`RAG_LOCAL_BACKEND` выбирает `torch` (прежнее поведение, по умолчанию)
или `onnx`. Выбор распространяется только на локальные вычисления RAG;
API-провайдеры эмбеддингов продолжают работать через свой API.

## Проверка на Windows с Radeon

1. В настройках RAG выберите «Бэкенд локального RAG» → `onnx`.
2. Для «Устройство ONNX для RAG» выберите `dml`, чтобы отсутствие DirectML
   стало явной ошибкой. `auto` выбирает DirectML при наличии провайдера,
   иначе использует CPU; `cpu` позволяет сравнить результат на процессоре.
3. Через AI Hub установите выбранную модель эмбеддингов и, если он включён,
   выбранную модель реранкера. Установщик использует существующий управляемый
   ONNX-бэкенд. На Windows он устанавливает ONNX Runtime DirectML.
4. Дождитесь окончания установки и перезапустите NeuroMita.
5. Проверьте строки `[RAG][ONNX] Loaded` в `Logs/NeuroMitaLogs.log`:
   там указаны модель, путь экспорта и провайдер. При отдельном процессе RAG
   его служебный лог находится в `Logs/AIWorkers/rag.log`.
6. Повторите поиск памяти и диалог между Митами. Сравните время ответа
   и наличие таймаутов с режимом `cpu` и с отключённым реранкером.

Наличие `DmlExecutionProvider` в сессии подтверждает подключение провайдера,
но не гарантирует выполнение каждого оператора на GPU: ONNX Runtime может
передавать неподдерживаемые операции CPU. Реальное ускорение нужно измерять
на целевой видеокарте.

## Установка и модели

Исходная HF-модель сохраняет прежний идентификатор. При установке ONNX-пути
Optimum экспортирует её на CPU в отдельный каталог
`checkpoints/rag_onnx/<embeddings|reranker>/<hash>/`. На запросах экспорт и
скачивание не выполняются. Для Qwen 0.6B экспорт требует нескольких гигабайт
свободной памяти и дополнительного места на диске; исходные веса и ONNX-копия
хранятся отдельно.

Задачи экспорта: `feature-extraction` для эмбеддингов,
`text-classification` для обычных cross-encoder моделей и `text-generation`
без KV-кэша для Qwen3-Reranker. Реранкер Qwen использует вероятности токенов
`yes`/`no`, как PyTorch-путь. Эмбеддинги используют тот же CLS/last-token pooling
и L2-нормализацию. Семантические настройки и ключ модели в базе не меняются.

Установка идёт в отдельном отменяемом процессе. Готовность экспорта проверяется
по манифесту и размерам всех файлов, включая внешние веса. Новый экспорт
публикуется после завершения подготовки; повреждённый экспорт можно
переустановить через AI Hub. Ошибка установки не заменяет прежний экспорт.

Сессии DirectML создаются с `ORT_SEQUENTIAL` и отключённым memory pattern.
Вызовы одной сессии сериализованы. Для DirectML эмбеддинги и для ONNX-реранкера
используется размер батча 1, чтобы ограничить расход памяти. Режим INT8 через
bitsandbytes относится к PyTorch и не включается в ONNX-пути.

Произвольная кастомная HF-модель должна поддерживаться экспортёром Optimum.
Поддержка PyTorch сама по себе не гарантирует успешный экспорт или выполнение
графа в DirectML. Ошибка экспорта или выполнения должна оставаться видимой;
автоматического перехода на PyTorch нет.

## Таймауты

В настройках RAG доступны `RAG_EMBED_TIMEOUT_SEC` (по умолчанию 60 секунд)
и `RAG_RERANK_TIMEOUT_SEC` (по умолчанию 0 — автоматический расчёт по числу
кандидатов). Положительные значения ограничены диапазоном 1–3600 секунд.
Изменения применяются к следующим запросам без перезапуска приложения.

Таймаут эмбеддингов применяется к обоим локальным бэкендам и запасному
локальному обработчику. Фоновые пакеты могут получать больше времени по числу
текстов. Один и тот же бюджет передаётся в AI engine и используется при
ожидании результата: повышение выше 300 секунд не обрезается прежним
стандартным дедлайном worker-запроса. Время включает ожидание в очереди.
Прогрев и установка имеют отдельные бюджеты ожидания.

Для диагностики на CPU можно выставить 300 секунд на эмбеддинги и 600 секунд
на реранкер. Это увеличивает допустимое ожидание, но не ускоряет вычисления.

## Передача тестеру

Поверх актуальной Python-сборки ветки `releases` достаточно заменить
`NeuroMita.pyz`, предварительно закрыв приложение. Изменения launcher,
`run.py`, `requirements.txt` и Unity для этой доработки не нужны. Для отката
сохраните прежний `.pyz`.

Проверка новых таймаутов на существующем PyTorch-пути не требует установки
ONNX. Для ONNX после замены `.pyz` нужно выбрать бэкенд и установить модели
через AI Hub: необходимые пакеты и экспорты не входят в `.pyz`. Нужны интернет,
свободное место на диске и время для первоначального экспорта на CPU.

## Границы проверки

Покрыты выбор бэкенда и установка зависимостей, параметры DirectML-сессии,
формирование входов, pooling и нормализация, расчёт оценок реранкеров,
готовность и восстановление экспортов. Небольшой ONNX-граф выполнен настоящим
ONNX Runtime на CPU по пути с кириллицей. Токенизатор в этом тесте заменён
тестовым адаптером.

Экспорт настоящих Qwen-весов, совместимость их графов с DirectML, потребление
VRAM и ускорение на Radeon пока не проверены. Приоритетная очередь остаётся
общей для вычислений RAG; её правила не меняются.

Источники: [требования DirectML к сессии](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html),
[Optimum main_export](https://huggingface.co/docs/optimum-onnx/onnx/package_reference/export),
[конфигурации экспортёра, включая Qwen3](https://github.com/huggingface/optimum-onnx/blob/main/optimum/exporters/onnx/model_configs.py).
